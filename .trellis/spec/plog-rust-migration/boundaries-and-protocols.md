### 2.2 Rust 边界

**职责范围**:
- API 请求处理
- 用户认证授权
- 业务逻辑执行
- 数据验证
- 数据库写入
- 缓存管理
- 任务调度

**边界规则**:
1. 所有外部请求必须通过 API 网关
2. 不直接暴露数据库连接
3. 不直接访问 PHP 代码
4. 通过 HTTP 与 PHP 通信

### 2.3 PHP 边界

**职责范围**:
- 老系统兼容
- 老插件执行
- 老主题渲染
- 请求转发
- 响应转换

**边界规则**:
1. 只读数据库，不直接写入
2. 通过 HTTP 调用 Rust 服务
3. 不引入新的业务逻辑
4. 保持向后兼容

### 2.4 数据层边界

**职责范围**:
- 数据持久化
- 数据缓存
- 文件存储

**边界规则**:
1. 写入操作主要通过 Rust
2. PHP 只读，特殊情况需审批
3. 缓存失效策略统一管理
4. 文件存储路径标准化

## 3. 交互协议

### 3.1 PHP ↔ Rust 通信协议

#### 3.1.1 协议选择

**推荐**: HTTP/JSON

**原因**:
1. 标准化程度高
2. 调试简单
3. 团队熟悉
4. 工具链完善

**不推荐**: FFI, gRPC (初期)

#### 3.1.2 请求格式

```http
POST /api/v2/resource HTTP/1.1
Host: rust-api.internal:8080
Content-Type: application/json
Authorization: Bearer <token>
X-Request-ID: <uuid>
X-Source: php-compat

{
  "data": {
    // 请求数据
  }
}
```

#### 3.1.3 响应格式

**成功响应**:
```json
{
  "success": true,
  "data": {
    // 响应数据
  },
  "meta": {
    "request_id": "uuid",
    "timestamp": "2026-03-29T10:00:00Z"
  }
}
```

**错误响应**:
```json
{
  "success": false,
  "error": {
    "code": "VALIDATION_ERROR",
    "message": "请求数据验证失败",
    "details": [
      {
        "field": "title",
        "message": "标题不能为空"
      }
    ]
  },
  "meta": {
    "request_id": "uuid",
    "timestamp": "2026-03-29T10:00:00Z"
  }
}
```

### 3.3 缓存协议

#### 3.3.1 缓存分层

```
┌─────────────────────────────────────────────────────────────┐
│                    缓存分层架构                               │
├─────────────────────────────────────────────────────────────┤
│                                                               │
│  L1: 应用缓存 (In-Memory)                                    │
│  ├── Rust: HashMap, LRU Cache                               │
│  └── PHP: APCu, OPcache                                     │
│                                                               │
│  L2: 分布式缓存 (Redis)                                      │
│  ├── Rust: redis-rs                                         │
│  └── PHP: phpredis                                          │
│                                                               │
│  L3: 数据库缓存 (MySQL Query Cache)                          │
│  └── 统一由 MySQL 管理                                       │
│                                                               │
└─────────────────────────────────────────────────────────────┘
```

#### 3.3.2 缓存失效策略

| 缓存类型 | 失效策略 | 负责方 |
|----------|----------|--------|
| 用户 Session | TTL + 手动失效 | Rust |
| 文章内容 | 写入时失效 | Rust |
| 分类列表 | 定时刷新 | Rust |
| 配置信息 | 写入时失效 | Rust |
| 搜索索引 | 定时重建 | Rust |

#### 3.3.3 缓存键规范

```
格式: {service}:{resource}:{id}:{attribute}

示例:
- rust:user:123:profile
- rust:post:456:content
- rust:category:list
- php:plugin:config:example-plugin
```

### 3.4 任务队列协议

#### 3.4.1 任务类型

| 任务类型 | 生产者 | 消费者 | 优先级 |
|----------|--------|--------|--------|
| 邮件发送 | Rust | Rust Worker | 中 |

| 搜索索引 | Rust | Rust Worker | 低 |
| 缓存预热 | Rust | Rust Worker | 低 |
| 数据导出 | Rust | Rust Worker | 低 |

### 3.5 错误处理协议

#### 3.5.1 错误码规范

| 错误码 | 说明 | HTTP 状态码 |
|--------|------|-------------|
| AUTH_REQUIRED | 需要认证 | 401 |
| AUTH_FAILED | 认证失败 | 401 |
| PERMISSION_DENIED | 权限不足 | 403 |
| NOT_FOUND | 资源不存在 | 404 |
| VALIDATION_ERROR | 数据验证失败 | 422 |
| INTERNAL_ERROR | 服务器内部错误 | 500 |
| SERVICE_UNAVAILABLE | 服务不可用 | 503 |

#### 3.5.2 错误传播

```
┌─────────────────────────────────────────────────────────────┐
│                    错误传播路径                               │
├─────────────────────────────────────────────────────────────┤
│                                                               │
│  Rust 内部错误                                               │
│  ├── 数据库错误 → DatabaseError → 500                       │
│  ├── 验证错误 → ValidationError → 422                       │
│  ├── 认证错误 → AuthError → 401                             │
│  └── 业务错误 → BusinessError → 400                         │
│                                                               │
│  Rust → PHP 错误                                             │
│  ├── 将 Rust 错误转换为 JSON 响应                            │
│  ├── 保持错误码一致                                          │
│  └── 记录错误日志                                            │
│                                                               │
│  PHP → Rust 错误                                             │
│  ├── HTTP 错误状态码                                         │
│  ├── JSON 错误响应体                                         │
│  └── 超时处理                                                │
│                                                               │
└─────────────────────────────────────────────────────────────┘
```

## 4. 接口规范

### 4.1 API 版本管理

#### 4.1.1 版本策略

```
URL 版本: /api/v1/*, /api/v2/*

版本生命周期:
- v1: 维护模式，Phase 4 结束后下线
- v2: 活跃开发，Phase 2 开始
- v3: 预留，未来扩展
```

#### 4.1.2 版本迁移

```
Phase 1-2: v1 和 v2 并行
Phase 3:   v2 为主，v1 兼容
Phase 4:   v1 下线，v2 升级为 /api/*
```
