# emLog Monorepo 架构设计文档

## 🎯 目标

将 emLog 从传统 PHP CMS 重构为：

- 模块化内容平台
- 前后端分离后台
- 插件 / 主题可扩展系统
- 支持现代开发流程（类似 Vite 思路）

---

## 🧠 核心设计原则

### 1. 分离三种状态

- 开发态（Dev）
- 构建态（Build）
- 运行态（Runtime）

### 2. Manifest 驱动

所有模块通过 manifest 描述：

- 插件
- 主题
- 后台模块
- 前端构建产物

### 3. 插件系统一等公民

插件必须支持：

- 生命周期
- 权限扩展
- 菜单扩展
- API 扩展
- UI 扩展

---

## 🔧 分层说明

### apps/

入口层：

- admin-web：后台前端
- admin-api：后台接口
- site-runtime：前台渲染

---

### packages/

核心能力层：

| 包 | 作用 |
|----|------|
| core | 容器、事件、hook、启动流程 |
| db | 数据库、迁移 |
| auth | 认证授权 |
| content | 文章系统 |
| plugin-kit | 插件 SDK |
| theme-kit | 主题 SDK |
| admin-sdk | 后台扩展 SDK |

---

🧠 总结

emLog 应重构为：

核心内核 + 插件系统 + 后台平台 + manifest 驱动架构

而 monorepo 是实现边界清晰的手段，而不是目标。
